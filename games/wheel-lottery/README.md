# 转盘抽奖：多转盘配置

前台可以选择不同转盘，后台可以管理当前浏览器保存的本地转盘。项目仍为纯静态页面，无需构建或后端。

## 使用方式

- 前台点击右下角设置按钮左侧的 🎡 按钮，展开的列表同时显示云端转盘和本地转盘，按去掉首尾空格后的名称去重，**云端优先**。
- 现有云端转盘为“星喵幸运转盘”和“不怕死挑战”。
- 后台可以查看云端配置，但只能编辑、重命名或删除本地转盘。
- 点击“复制为本地转盘”时必须使用不同的名称。新建、改名、复制和导入均不允许与任何云端或其他本地转盘重名。
- 新建、复制和导入先生成草稿，点击“保存配置”后才持久化。切换或离开页面时会提示未保存的修改。
- 后台展开“调整转盘显示顺序”，使用上移、下移按钮排序。顺序自动保存，只影响当前浏览器，可以混排云端和本地转盘。
- 前台记住选择；抽奖记录按转盘分开，刷新页面后清空。抽奖开始至结果弹窗关闭期间不能切换转盘。
- 同源的另一标签页保存配置后，前台自动更新；若正在抽奖，则在关闭结果后更新。
- 本地数据与排序不跨设备同步。需要转移单个配置时，可以导出 JSON，再在另一浏览器导入。

## 云端配置维护

`config/wheels.json` 的数组顺序是新浏览器的默认显示顺序。例如：

```json
{
  "wheels": [
    { "id": "classic", "name": "星喵幸运转盘", "file": "prizes.json" },
    { "id": "challenge", "name": "不怕死挑战", "file": "challenge.json" }
  ]
}
```

新增云端转盘时：

1. 在 `config/` 中放入转盘 JSON 文件，结构与 `prizes.json` 一致。
2. 在清单中添加唯一、稳定的 `id`，填写名称和文件名。文件名使用英文字母、数字、下划线或连字符，扩展名为 `.json`。
3. 清单名称须与配置的 `settings.title` 一致，云端名称应保持唯一。
4. 调整清单数组顺序即可修改默认排序。已经在浏览器保存的自定义排序优先，新增加的转盘会追加到未排序项中。

转盘 `id` 用于保持排序和选择状态，改名时不要更换 `id`。所有奖项概率之和必须为 100%，奖项编号不得重复。

## 数据兼容和故障处理

- 新数据保存在 `wheel-lottery-library-v2`，包含本地转盘、显示顺序、上次选择和迁移标志。
- 原来的 `wheel-lottery-config` 会自动迁移为一个本地转盘；遇到重名时添加“（本地）”或带序号的后缀，保留原有内容。
- 旧键保留作备份，迁移标志避免重复导入。删除迁移后的本地转盘不会再次导入。
- 如果未来新增的云端转盘与已有本地转盘同名，前台显示云端版。本地版仍在后台保留，并标明“同名，改名后显示”。
- 云端清单或配置未完整加载时，页面显示已加载的配置，但暂停新建、复制和保存，避免漏检云端名称。刷新后重试。
- 本地数据损坏或存储空间不足时显示错误，不以新的空数据覆盖原有内容。

## 代码与验证

- `js/wheel-store.js`：共享配置加载、数据迁移、名称规则、本地持久化和排序。
- `js/wheel-library.js`：前台选择、记录隔离及跨标签页更新。
- `js/admin-library.js`：后台本地管理、草稿保护、导入及排序操作。

在仓库根目录用 Node.js 运行数据逻辑测试：

```powershell
node --test games/wheel-lottery/tests/wheel-store.test.cjs
```

本地查看页面：

```powershell
python -m http.server 8000
```

访问 `http://localhost:8000/games/wheel-lottery/`，点击齿轮进入后台。
